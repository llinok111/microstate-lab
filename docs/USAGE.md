# Usage

## Installation

```bash
npm install        # dev dependencies: esbuild, sharp (figures only)
npm run build      # produces dist/
```

`dist/` contains three entry points, so a page pays only for what it imports:

| File | Size | Purpose |
|---|---|---|
| `microstate.js` | 79.1 KB (19.7 KB gz) | Components + motion core, programmatic API |
| `microstate-auto.js` | 63.1 KB (15.3 KB gz) | Declarative runtime: `data-ms` attributes |
| `microstate-elements.js` | 66.8 KB (15.5 KB gz) | Custom elements: `<ms-button>` etc. |
| `microstate.css` | 11.1 KB (2.8 KB gz) | Component styles (shared by all three) |

The three JS entry points deliberately do **not** re-export each other. Re-exporting
the runtime from the main bundle grew it from 72 KB to 94 KB, so a page that only
wanted `mountPress` would have paid for a `MutationObserver` and nine custom-element
classes it never used.

No runtime dependencies. No web fonts, no icon fonts, no external requests.

`package.json` maps them as subpath exports:

```js
import { mountPress } from "microstate-lab";          // programmatic
import { start } from "microstate-lab/auto";          // declarative
import "microstate-lab/css";
```

## Declarative usage (v0.2)

For most pages this is the whole integration: one stylesheet, one script, and
attributes.

```html
<link rel="stylesheet" href="dist/microstate.css">
<script type="module">
  import { start, registerAction } from "dist/microstate-auto.js";
  registerAction("save", () => fetch("/api/save", { method: "POST" }));
  start(document);
</script>

<button data-ms="press" data-ms-duration="180" data-ms-easing="ease-out">Continue</button>
<button data-ms="async-button" data-ms-action="save">Save changes</button>
<button data-ms="switch" data-ms-persist="autosave">Auto-save drafts</button>
<div data-ms="disclosure" data-ms-title="Delivery options"></div>
<ul data-ms="drag-sort"><li>Draft</li><li>Review</li><li>Done</li></ul>
```

### Attributes

| Attribute | Values | Applies to |
|---|---|---|
| `data-ms` | component name | all |
| `data-ms-duration` | ms, or `auto` (springs) | all |
| `data-ms-delay` | ms | all |
| `data-ms-easing` | keyword, `cubic-bezier(…)`, `spring(…)`, `steps(…)` | all |
| `data-ms-trigger` | `press` `click` `hover` `focus` `enter` `manual` | all |
| `data-ms-reduced` | `instant` `fade` `off` `ignore` | all |
| `data-ms-distance` / `data-ms-scale` | number | travel / scale effects |
| `data-ms-action` | registered action name | `async-button` |
| `data-ms-persist` | storage key | `switch` |
| `data-ms-effect` | `press` `lift` `shake` | `press` |
| `data-ms-title` | string | `disclosure` |

`start(root, { defaults })` supplies fallbacks for every element, which is the
cheapest way to set a house style:

```js
start(document, { defaults: { reduced: "fade", easing: "cubic-bezier(.2,.8,.2,1)" } });
```

### What the runtime does with your element

It **replaces** the host element with the component's control, carrying over:

- the host's `class` list (except `ms-*`, which the component owns)
- `id`, `name`, `aria-label`, `title`, `type`, and any other author attributes
- `data-ms-persist`, `data-ms-action` and the other config attributes

Replacement rather than nesting is deliberate: `<button><button></button></button>`
is invalid HTML and the inner button is not focusable in every browser. The cost
is that a reference you captured before boot points at a detached node — so boot
before you query, or query after `start()`.

### Late insertion

Anything added after `start()` is picked up by a `MutationObserver`, coalesced to
one scan per animation frame. `data-ms-bound` marks what has been mounted, so a
re-scan never double-binds.

```js
container.append(makeButton());   // mounted on the next frame, no call needed
```

### Registering your own component

```js
import { register } from "microstate-lab/auto";

register("counter", (host, { motion, behaviour }) => {
  const btn = document.createElement("button");
  btn.className = "ms-btn";
  let n = 0;
  btn.textContent = `Clicked ${n} times`;
  btn.addEventListener("click", () => { btn.textContent = `Clicked ${++n} times`; });
  host.replaceWith(btn);
  return { teardown: () => btn.remove() };
});
```

```html
<button data-ms="counter" data-ms-duration="200">Clicked 0 times</button>
```

`register()` returns an unregister function, which is what a test needs between
cases.

## Custom elements

Same attribute contract, different ergonomics. Use these when the markup is not
generated by something that validates tags, or when you want
`connectedCallback` / `disconnectedCallback` lifecycle for free.

```js
import { defineAll } from "microstate-lab/elements";
defineAll();   // or defineAll(["ms-switch", "ms-button"])
```

```html
<ms-switch data-ms-duration="auto" data-ms-easing="spring(1, 320, 17)">Weekend mode</ms-switch>
<ms-drag-sort><ul><li>Draft</li><li>Done</li></ul></ms-drag-sort>
```

`defineAll()` skips names that are already defined, so loading the script twice
(a bundler plus a `<script>` tag) is harmless.

Prefer `data-ms` on native elements when you can. A native `<button>` keeps form
participation, `type="submit"` and default Enter behaviour, and it renders
correctly before the script loads — a custom element renders as an unstyled
unknown tag until it upgrades.

## Preferences — the site's own reduced-motion setting

The OS setting is not the only signal worth honouring, but it is the one that
must never be overridden.

```js
import { writePreference, readPreference, watchPreference, resolvePreference } from "microstate-lab";

writePreference("reduce");   // "system" | "reduce" | "allow"
readPreference();            // → "reduce"

// Explain the decision in a UI, rather than silently changing behaviour.
const { reduced, source } = resolvePreference({
  osPrefers: matchMedia("(prefers-reduced-motion: reduce)").matches,
  stored: readPreference(),
});
// source: "os" | "preference" | "default"
```

**The rule is asymmetric on purpose.** A stored preference can add restraint but
never lift an OS reduce:

| OS says | stored | result |
|---|---|---|
| reduce | `allow` | **reduced** (source: `os`) |
| reduce | `system` | reduced |
| no preference | `reduce` | reduced (source: `preference`) |
| no preference | `allow` | motion allowed |
| no preference | `system` | default |

A site that stores "animations on" and then ignores the system preference has
taken a decision away from the user. That is the failure mode this table exists
to prevent, and it is covered by a test that iterates every stored value.

`writePreference` returns `false` when storage is unavailable (Safari private
mode, blocked site data) rather than throwing — reflect that in the UI instead
of showing a toggle that silently did nothing.

## Persistent component state

```html
<button data-ms="switch" data-ms-persist="autosave">Auto-save</button>
```

Stored under `ms:state:switch:autosave` with a version envelope, so a future
shape change is detectable instead of being misread as valid.

```js
import { persist, restore, forget } from "microstate-lab";

persist("table:density", "compact");
restore("table:density", "comfortable");   // → "compact"
forget("table:density");
```

`restore()` returns the fallback for missing, corrupt or foreign values — a bad
record must not break boot.

## Mounting a component

Every component follows the same contract:

```js
const instance = mountX(containerElement, options);

instance.el;            // the root element it created
instance.setMotion();   // change the motion spec live, no remount
instance.getState();    // current component state + the resolved plan
instance.destroy();     // remove nodes and all listeners
```

### Press

```js
import { mountPress } from "./dist/microstate.js";

mountPress(document.querySelector("#slot"), {
  label: "Continue",
  variant: "primary",       // "primary" | "plain"
  effect: "press",          // "press" | "lift" | "shake"
  motion: {
    duration: 180,          // ms
    delay: 0,               // ms
    easing: "ease-out",
    reduced: "instant",     // strategy under prefers-reduced-motion
    trigger: "press",       // fires on pointerdown / keydown, not on release
    scale: 0.97,
  },
});
```

`effect: "shake"` binds to click instead of press — a rejection while the finger is still down fires before the action was attempted. `effect: "lift"` binds to pointer enter.

### Async button

```js
import { mountAsyncButton } from "./dist/microstate.js";

const save = mountAsyncButton(slot, { label: "Submit", succeedAfter: 400 });

await save.trigger({ fail: false });   // programmatic run
save.getState();                        // { state: "idle" | "loading" | "success" | "error", plan }
```

The button keeps a fixed width across all four states so the surrounding layout does not reflow. It uses `aria-disabled` rather than `disabled` so focus is preserved mid-flight.

### Disclosure

```js
import { mountDisclosure } from "./dist/microstate.js";

const panel = mountDisclosure(slot, {
  title: "Delivery options",
  items: ["Standard — 3 to 5 days", "Express — next day"],
  motion: { duration: 260, easing: "cubic-bezier(.2,.8,.2,1)", reduced: "fade" },
});

panel.toggle();
panel.getState();   // { open, expanded: "true"|"false", hidden }
```

Height is measured from `scrollHeight` and cleared after the transition, so content changes reflow correctly. The panel is `hidden` only after the exit animation completes.

### Switch

```js
import { mountSwitch } from "./dist/microstate.js";

const sw = mountSwitch(slot, { label: "Auto-save drafts", checked: false });

sw.toggle();
sw.setChecked(true, { animate: false });   // idempotent; no-op if already on
sw.getState();                             // { on, ariaChecked, plan }
```

Rendered as a real `<button role="switch">` — it gets Space activation, `aria-checked` announcement and tab order for free.

### Drag-sort

```js
import { mountDragSort } from "./dist/microstate.js";

const list = mountDragSort(slot, {
  items: ["Draft", "In review", "Approved", "Published"],
  motion: { duration: 220, easing: "cubic-bezier(.2,.8,.2,1)" },
});

list.getState();   // { order: [...], grabbed: number | null }
```

Pointer dragging and a keyboard path are both supported: `Space` grabs, `↑`/`↓` moves, `Space` drops, `Escape` restores the original order. Focus stays on the moved row, so moves can be chained.

### Error feedback and toast

```js
import { mountErrorFeedback, mountToast } from "./dist/microstate.js";

const field = mountErrorFeedback(slot, { label: "Work email" });
field.showError("That address is missing a domain.");
field.clearError();

const toast = mountToast(slot, {});
toast.push("success", "Changes published");
toast.push("error", "Publish failed — retry");
```

The error field sets `aria-invalid`, links the message via `aria-describedby`, announces assertively and moves focus to the input. Toasts pause their dismissal timer on hover and focus, and are dismissible with `Escape` (WCAG 2.2.1 — a timed dismissal with no way to pause is a failure).

## Motion spec reference

```ts
type MotionSpec = {
  duration?: number;         // 0..4000 ms, default 240
  delay?: number;            // 0..2000 ms, default 0
  easing?: string;           // see below, default "ease-out"
  reduced?: "instant" | "fade" | "off" | "ignore";
  trigger?: "press" | "click" | "hover" | "focus" | "enter" | "manual";
  iterations?: number;       // 1..n, or Infinity
  distance?: number;         // 0..64 px, for travel-based effects
  scale?: number;            // 0.5..1.5, for scale-based effects
};
```

Out-of-range values are clamped, not rejected. Non-numeric values fall back to the default rather than becoming `NaN` — a `NaN` duration silently produces no animation, which is harder to debug than a clamped value.

### Easing forms

```js
"ease-out"                       // keyword; exported verbatim
"cubic-bezier(.2, .8, .2, 1)"    // solved per frame
"spring(1, 300, 16)"             // mass, stiffness, damping
"steps(4)"                       // quantised
"steps(6, start)"
```

Invalid input throws at `plan()` time with the offending value in the message, rather than producing a silently broken animation.

### Reduced-motion strategies

| Strategy | Behaviour | Use when |
|---|---|---|
| `instant` | State applies immediately, transition removed | The state is legible without motion (press, toggle) |
| `fade` | Movement dropped, 90 ms opacity retained | Something must signal that content appeared |
| `off` | Nothing animates | The motion carries no state (decorative shake) |
| `ignore` | Animates regardless | Lab inspection only |

## Core API

Useful when building a component that is not in this library.

```js
import { plan, play, keyframesFor, parseEasing, sample } from "./dist/microstate.js";

// 1. Resolve a spec into a concrete plan (pure, no DOM).
const p = plan({ duration: 240, easing: "spring(1, 300, 16)", reduced: "instant" });

p.effective;      // { duration, delay, easing, cssEasing, iterations, ... }
p.reduced;        // true when motion was actually suppressed
p.osPrefers;      // true when the OS asked for reduce (may differ from `reduced`)
p.notes;          // human-readable list of any downgrades
p.isStatic;       // true when duration resolved to 0

// 2. Play it. Guarantees the end state is applied even if cancelled.
const handle = play(el, keyframesFor("press", { scale: 0.95 }), p, {
  key: "press",
  policy: "latest",       // "latest" | "queue" | "lock"
});

await handle.finished;    // { status: "finished" | "cancelled" | "static" }
handle.cancel();          // leaves the element at the final keyframe

// 3. Inspect a curve for plotting.
sample(parseEasing("spring(1, 300, 16)"), 64);   // 65 numbers in 0..1+
```

`plan()` never touches the DOM, so it is fully testable in Node — 24 of the 74 unit tests exercise it without a browser.

## Exporting

```js
import {
  exportCss,
  exportJs,
  exportStandaloneHtml,
  exportConfig,
  exportAll,
  exportBundle,
} from "microstate-lab";

const css = exportCss("press-soft", { duration: 240 });
css.css;         // full stylesheet, including the reduced-motion block
css.className;   // "ms-press-soft"
css.notes;       // array of human-readable caveats

const bundle = exportAll("press-soft", { duration: 240 });
bundle.html;     // complete page, runs from file://
```

### Several interactions in one stylesheet

```js
const merged = exportBundle([
  { preset: "press-soft", motion: { duration: 180 } },
  { preset: "toggle-spring" },              // duration comes from the physics
  { preset: "disclose-height", motion: { delay: 40 } },
]);

merged.css;         // one file, one header, namespaced classes
merged.manifest;    // [{ preset, className, notes }]
merged.conflicts;   // duplicate class names, if any (there should be none)
```

Each preset keeps its **own** `@media (prefers-reduced-motion: reduce)` block,
because the strategies differ — `instant`, `fade` and `off` are three different
answers, and collapsing them into one block would silently pick one.

### CLI

```bash
npx microstate list                                    # presets + resolved timings
npx microstate css press-soft --duration 200 -o out.css
npx microstate css press-springy --duration auto       # physics decides
npx microstate html toggle-spring -o demo.html
npx microstate bundle interactions.json -o interactions.css
npx microstate check                                   # export every preset, fail on error
```

`interactions.json`:

```json
{
  "press-soft": { "duration": 180 },
  "toggle-spring": {},
  "disclose-height": { "delay": 40 }
}
```

Exit codes are part of the contract, so `check` works in CI: `0` success, `1`
bad arguments or unknown preset, `2` a preset failed to export.

### Deep links

The lab keeps its state in the URL, so a tuned configuration can be shared
without pasting JSON:

```
?p=press-springy&d=504&e=spring(1,300,16)&t=press&r=instant
```

Only values that differ from the preset default are written, so a default state
has a clean URL. An unknown preset in a link is ignored rather than breaking the
page.

### Using the CSS export

```html
<link rel="stylesheet" href="ms-press-soft.css">
<button class="ms-press-soft" type="button">Continue</button>

<script>
  const btn = document.querySelector(".ms-press-soft");
  btn.addEventListener("click", () => {
    btn.classList.add("is-running");
    btn.addEventListener("animationend", () => btn.classList.remove("is-running"), { once: true });
  });
</script>
```

For `trigger: "hover"` and `"focus"` no JS is needed — the selector does the work.

For `trigger: "press"` the export ships four lines of JS plus a comment: CSS has no "held" state, so a class toggle cannot express press-and-release. Switching the trigger to `click` removes the need for JS entirely.

## Running the lab

```bash
npm run build
# then open demo/index.html, or serve it:
npx serve demo
```

The lab works from `file://` — it uses plain `<script type="module">` with relative paths and no import map.

Controls:

- **Left column** — 21 presets across 7 families; the badge marks counter-examples.
- **Centre** — the live component. `重新挂载` remounts, `复制配置` copies the JSON spec.
- **Right column** — duration, delay, easing (with a live curve plot), trigger, reduced-motion strategy, loop, distance, scale.
- **Bottom** — export panel with CSS / JS / HTML / JSON tabs, copy, download, and "run in a new tab".
- **Top right** — reduced-motion policy override (`respect` / `ignore` / `force`) and a high-contrast toggle.

The `force` policy simulates a reduce preference without changing your OS settings, so the reduced-motion behaviour can be audited on a normal machine.

### Debug hooks

`window.__lab` exposes `state`, `mount`, `applyMotion`, `selectPreset`, `readControls` and `getLastPlan()` — enough for a test or a console session to inspect what the lab resolved, without reaching into module internals.

## Troubleshooting

**The spring looks different from the export.** Expected at low sample density — a spring is exported as `linear()`. Increase density via `toLinear(fn, 64)`, or accept the approximation; the notes panel states when it happened.

**`CSS.supports` reports no `linear()` support.** The export falls back to a `cubic-bezier` approximation and says so in the notes. Safari 15.4+ and Chrome 113+ support `linear()`.

**Nothing animates in a unit test.** `play()` detects a missing `element.animate` and applies the end state synchronously instead of throwing, so component logic still works under jsdom. Assertions about *animation* belong in the browser suites.

**Handlers run twice.** `mountX` appends nodes; call `destroy()` before remounting onto the same container. The lab's `重新挂载` button does this correctly.
